# UDRA Viewer

An Expo app (SDK 57, runs in Expo Go) that shows one UDRA coaching-app screen full screen: a client's body scan,
Muscle tab, with a live 3D anatomy model. The screen itself is a web page in `screen/`, shown in a full-screen WebView.

## Run

`npm start` — packs `screen/`, starts a live-reload server for it on port 8090, and starts Expo. While it runs,
the phone loads the screen from that server: **saving any file in `screen/` reloads the phone automatically.**
Edits to `App.js` hot-reload through Expo as usual. Phone and computer must be on the same Wi-Fi
(with `npm run start:tunnel` the app falls back to the bundled copy, without live reload).

## Where things are

- `screen/index.html` — the whole screen. This is the file to edit for UI changes.
  - `<template id="screen-tpl">` — the markup (all inline styles). Template syntax: `{{name}}` holes filled from
    `renderVals()`; `<sc-if value="{{cond}}">`; `<sc-for list="{{items}}" as="x">` (use `{{x.field}}`);
    events like `onClick="{{handler}}"`; `ref="{{fn}}"`. Holes are plain lookups (`a.b`), not expressions:
    compute values in `renderVals()` and return them.
  - `<script>` with `class Component extends DCLogic` — state and logic. `renderVals()` returns every value
    the template uses. Demo data: `REG` (VALD strength tests, forces in N), `AREAS` (10 body-area chips).
    The bottom sheet follows the header tab too: Overview (one summary card per assessment), U-Body (Bodydot posture:
    `POSTURE`, `POSTURE_AREAS`, fields and normal ranges from the 3D-Model repo's `app/posture.ts`), U-Muscle (VALD `REG`), U-Nutrition (InBody segmental fat `SEGMENTS`, from that repo's `InBodyResult`).
    U-Muscle and U-Body each end with their program, generated by rules ported from the VALD-automator repo
    (`VALD_EX`/`valdDose` from web/backend/program_builder.py; `BD_RANGE`/`bdGrade` and the Bodydot exercise rules from
    web/frontend/src/bodydot/program.html). Change the rules there first, then port them.
    Layers follow the header tab (`LAYERS_OF`: Overview all (the default), U-Body skeleton, U-Muscle muscle and skeleton, U-Nutrition all three).
    Layout constants near `const FH = ...` (header height `VT`, sheet snap heights `SH`).
  - The last `<script>` — `layout()` scales the 412 px-wide design to the phone width and passes
    `frameH`, `safeTop`, `safeBottom` (status bar / home indicator, in design px).
- `screen/dc-lite.js` — tiny runtime that renders the template with React 18. Rarely needs changes.
- `screen/udra-model.js` — compiled 3D model viewer (three.js). Don't edit; it's built from the separate 3D-Model repo.
  **One local patch:** its embed passed `pose:null` to the scene; it's changed to `pose:t.pose??null` so the screen can
  pose the body. Carry this into the 3D-Model repo's embed (or re-apply it) whenever udra-model.js is rebuilt.
- `screen/udra-posture.js` — the 3D-Model repo's Bodydot posture solver (`app/posture.ts` + `public/models/rig.json`),
  bundled with esbuild as `UDRAPosture.solve(values)` → bone matrices. Overview and U-Body pass them to the model
  (`postureMatrices()` in index.html). Don't edit; rebuild it from that repo if the solver or rig changes.
- `screen/model/` — model geometry (base64, ~28 MB). Don't edit.
- `screen/img/` — thumbnails from the old Layers menu (no longer used; the header tabs set the layers now).
- `App.js` — the native shell: full-screen WebView, first-launch install of the bundled copy, dev-server detection.
- `packed/`, `webfiles.js` — generated by `scripts/pack.js` from `screen/`. Never edit by hand.

## Design rules

UDRA brand: font Sora; Navy #122649, Blue #005EFF, Lime #CDFF20, Cyan #64E0FF, Flame #FF403C, Linen #EFECE6;
dark purple-black app look (#04050B header, #0D0E1A stage, #191B28 sheet); active pills are white with dark text;
Weaker side shows blue, stronger side red; 10% asymmetry is the flag threshold.
The screen is view-only (no add/assign buttons). Tap targets at least 44 px.

## Notes

- The model loader fetches `model/*.js`; a fetch shim in `index.html` serves those via script tags because
  WKWebView can't fetch `file://` URLs in the installed copy. Keep it.
- After editing, the bundled copy updates automatically (pack runs on every save), so the app also works without
  the computer's server next time it starts.
- 3D anatomy credit: BodyParts3D, © The Database Center for Life Science, CC BY 4.0. Keep it.
